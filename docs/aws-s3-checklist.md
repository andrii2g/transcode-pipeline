# S3 Checklist

Create private input and output buckets in the configured `S3Storage:Region`.

Required settings:

- Block Public Access enabled;
- bucket-owner-enforced object ownership;
- default server-side encryption matching `S3Storage:ServerSideEncryption`;
- CORS from `aws/s3/cors.json`, with the real browser origin;
- lifecycle policy from `aws/s3/lifecycle.json`;
- Standard SNS notification from `aws/s3/notification-configuration.json`.

The input notification must use `s3:ObjectCreated:*`, prefix `uploads/`, and the exact upload topic ARN. Its topic policy must allow only the expected bucket/account to publish.

Source keys are generated by the application:

```text
uploads/{videoId}/source/source.{validatedExtension}
```

The pre-signed POST policy enforces the exact key, `x-amz-meta-video-id`, content type when supplied, encryption, expiry, and `content-length-range` from 1 through the session maximum.

Validate:

```powershell
aws s3api head-bucket --bucket <input-bucket>
aws s3api head-bucket --bucket <output-bucket>
aws s3api get-public-access-block --bucket <input-bucket>
aws s3api get-bucket-encryption --bucket <input-bucket>
aws s3api get-bucket-notification-configuration --bucket <input-bucket>
```

The application role needs source inspection plus MediaConvert submission permissions from `aws/iam/application-policy.json`. MediaConvert uses its separate service role.
